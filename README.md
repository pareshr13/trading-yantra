# Trading Yantra — Marketing Website

Static, SEO-optimized marketing site for **Trading Yantra**, an AI/ML-powered stock
analysis product for NSE & BSE retail traders. Built with [Astro](https://astro.build)
+ [Tailwind CSS v4](https://tailwindcss.com) — ships as pre-rendered static HTML with
near-zero client-side JavaScript for the best possible Core Web Vitals / Lighthouse
scores (a direct Google ranking factor).

This is a **separate, standalone codebase** — it does not share code with, or depend
on, the `ai-stock-analyser` app. It only borrows that app's color/font language
(Inter + JetBrains Mono, emerald→teal→cyan gradient, dark navy theme) for a family
resemblance; the "Trading Yantra" name, logo, and copy are a distinct new brand.

## Pages

| Route | Purpose |
|---|---|
| `/` | Home — hero, feature highlights, how-it-works, stats, CTA |
| `/about` | About Us — mission, "radical honesty" philosophy, approach |
| `/product` | Product — AI/ML signals, indicators, candlestick & pattern research, FAQ |
| `/contact` | Contact Us — form + direct email |
| `/disclaimer` | Risk / no-advice disclaimer (India market — SEBI-adjacent) |
| `/privacy-policy` | Privacy policy |
| `/terms` | Terms of service |
| `/404` | Not found page |

## Getting started

```sh
npm install
npm run dev       # http://localhost:4321
npm run build     # outputs static site to ./dist
npm run preview   # preview the production build locally
```

## Before you go live — things to update

1. **Domain** — `astro.config.mjs`'s `site` field and `public/robots.txt`'s sitemap
   URL are placeholders (`https://tradingyantra.in`). Update both once you've
   registered/deployed to your real domain — the sitemap and every canonical/OG URL
   are derived from this.
2. **Contact form access key** — [`src/components/ContactForm.astro`](src/components/ContactForm.astro)
   posts to [Web3Forms](https://web3forms.com), a free static-form relay. Get a real
   access key (just needs an email, ~30 seconds) at web3forms.com and replace
   `WEB3FORMS_ACCESS_KEY` at the top of that file. Until you do, the form shows a
   friendly "email us directly" message instead of silently failing.
3. **Contact email** — `hello@tradingyantra.in` is used throughout (footer, contact
   page, legal pages). Update to your real inbox via a project-wide search for
   `tradingyantra.in`.
4. **Legal pages** — `/disclaimer`, `/privacy-policy`, and `/terms` are real,
   specific drafts (not lorem ipsum) written for an India-market, no-advice
   informational product, but **they are not a substitute for legal review**. Have a
   lawyer check them (especially the disclaimer) before launch, particularly if the
   underlying product later offers paid subscriptions, brokerage integration, or
   anything that could be read as investment advice.
5. **Brand assets** — the logo mark is defined as inline SVG in
   [`src/components/Logo.astro`](src/components/Logo.astro) and
   [`public/favicon.svg`](public/favicon.svg) (kept in sync manually — there are only
   two copies). PNG variants (app icons, Open Graph image) are generated by
   [`scripts/generate-assets.mjs`](scripts/generate-assets.mjs) — re-run
   `node scripts/generate-assets.mjs` after changing the mark's SVG path data to
   regenerate `public/logo/logo-192.png`, `public/logo/logo-512.png`, and
   `public/og-image.png`.
6. **Analytics** — none is wired up yet by design (see `/privacy-policy`). Add a
   privacy-respecting analytics snippet (e.g. Plausible, Fathom, or GA4) in
   `src/layouts/BaseLayout.astro` when you're ready, and update the privacy policy
   to match.

## Design system

- **Colors**: custom `ink`/`surface`/`line` navy tokens plus Tailwind's stock
  `emerald`/`teal`/`cyan`/`amber`/`rose` palettes, defined via Tailwind v4's CSS-first
  `@theme` block in [`src/styles/global.css`](src/styles/global.css) (no
  `tailwind.config.js` — Tailwind v4 doesn't use one by default).
- **Fonts**: Inter (UI/body) + JetBrains Mono (stats/data), loaded from Google Fonts.
- **Motion**: CSS-only keyframes (`candle-anim-*`, `trendline-anim`, `fade-in-up`)
  for the hero's floating-candlestick visual; respects `prefers-reduced-motion`. The
  only client JS on the site is the mobile menu toggle, the stat count-up animation,
  and the contact form's fetch submission — everything else is static HTML/CSS.
- **Components** live in `src/components/`, shared chrome in
  `src/layouts/BaseLayout.astro` (SEO meta + JSON-LD via `Seo.astro`, `Header.astro`,
  `Footer.astro`).

## SEO

- Per-page `<title>`/meta description/canonical/Open Graph/Twitter Card via
  [`src/components/Seo.astro`](src/components/Seo.astro).
- JSON-LD: `Organization` + `WebSite` on every page, `SoftwareApplication` +
  `FAQPage` on `/product`.
- Sitemap auto-generated at build time by `@astrojs/sitemap` (→ `sitemap-index.xml`);
  `robots.txt` points to it.
- Static HTML output, semantic landmarks, one `<h1>` per page, descriptive `alt`
  text, mobile-first responsive layout.

## Deployment

Any static host works — the `npm run build` output in `./dist` is plain HTML/CSS/JS.
Netlify, Vercel, Cloudflare Pages, or GitHub Pages all support Astro out of the box;
pick whichever matches how you plan to manage DNS for the real domain.
